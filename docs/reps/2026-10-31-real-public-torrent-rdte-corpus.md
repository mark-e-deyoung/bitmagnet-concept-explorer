# Real publisher torrent metainfo for CPE RDTE — 2026-10-31

**Authority:** Bitmagnet product DLE [bitmagnet-tools #18](https://github.com/mark-e-deyoung/bitmagnet-tools/issues/18); canonical Bitmagnet source plugins + importer in `bitmagnet-tools/scripts/sources/*.ps1`, `Sync-BitmagnetSources.ps1`; deferred lossless metainfo design [#9](https://github.com/mark-e-deyoung/bitmagnet-tools/issues/9); discovery proposals [#15](https://github.com/mark-e-deyoung/bitmagnet-tools/issues/15); public CPE research pack #6 and storage/federation CPE #348. This is a small source-specific **RDTE acquisition adapter**, NOT a second production source-orchestration framework.

## Use and source permissions

- **Public issuer metainfo**: actual `.torrent` files published by Canonical for Ubuntu 26.04.1 desktop and server. No invented hashes, no packaged ISO image bytes, no P2P activity. Exact SHA-1 calculated over original bencoded `info` bytes; original complete `.torrent` saved by SHA-256. Records pass through the actual Bitmagnet v0.10.0 `/import` and are queried through its real PostgreSQL/FTS and Explorer API. Any failed source fetch, parser validation or identity replay is a first failure. A license statement is reported only as a **source claim**.
- **Optional Internet Archive**: official Advanced Search and Metadata API, bounded first page of `prelinger` historical-film results which advertise `Archive BitTorrent`. Only items with a specific public-domain/CC0 `licenseurl` in the item metadata and a listed real `_archive.torrent` file can be admitted; all other items fail closed/skip. Internet Archive's own documentation says torrent generation is common but **not universal**, and files can change after derives. Unavailability does not fake Archive qualification. The first rep requires at least two bona fide Ubuntu objects; Archive candidates remain an independently observed optional source.
- **Other source families**: Debian ISO official torrents and FOSSTorrents are next candidates; the repository already has `linux-distro.ps1`, `FOSSTorrents.ps1`, `archive.ps1` and torrent export. RSS for shows, Nyaa/EZTV etc is *not* admitted into this **public redistributable** corpus merely because torrent metadata is publicly visible. Record policy/source terms/individual redistribution rights and avoid privileged/authenticated feeds or source-workaround techniques. No tracker requests, metadata peer discovery, magnet rehydration, payload downloads or seed/announce.
- **Security**: bound hosts, HTTPS, bounded download size/time, bencode decode budget, reject private/v2 metainfo until separately admitted, reject malformed/deduplicated entries, no script execution from feeds and no private source credentials.

## RDTE corpus layers

1. **L0 real immutable observations:** original `.torrent` bytes named `sha256.torrent`, native infohash, full SHA-256, source URL/record, asserted rights/license metadata, retrieval failures. A metainfo archive is NOT the distributed payload.
2. **L1 standardized Bitmagnet import and index:** exact real torrent infohash/name/size/contentType and source ID, genuine Bitmagnet rows and real Query/API/CLI; no fake torrent identities (except the explicitly separate 5 negative-test fixtures retained from #16, and the 232 metadata-only Gutenberg rows from #17).
3. **L2 CPE research projection:** source taxonomy and multilingual candidate terms, concept provenance/UNKNOWN/collisions/hard negatives; existing Gutenberg lore research pack remains `pinned-preview-not-normative`. Nothing writes accepted CPE Plane A/B/C facts or changes semantic policy.
4. **L3 reproducible evaluation:** fixed query/projection IDs, source observation hashes, real Bitmagnet version/digest, first failure, recall proxy/precision and prior accepted/declined proposals.
5. **L4 downstream replay:** consumer can verify object SHA-256, recompute bencoded infohash and import/index it in an isolated real Bitmagnet instance, build alternate CPE indexers or UI/agent flows, without accessing a live swarm.

## Recurrent public runner and durable custody design

- A twice-weekly `schedule` (04:43 UTC Tuesday/Friday), `workflow_dispatch`, and `pull_request` are in **this open draft**. GitHub only executes scheduled workflows from the default branch: this does **not turn on recurring collection until independent owner-reviewed merge**. The job is limited to real-source metadata-only, real upstream Bitmagnet/Explorer and existing public CPE research projection. No paid runners, no local endpoints, no private credentials, no public server, no source bypass.
- Job-only `actions/upload-artifact` preserves **the original binary metainfo, import NDJSON and manifest** for 14 days, establishing immediate repeat/review use while GHA runs are otherwise ephemeral. **This is not long-term archival storage**; GitHub Actions artifacts and logs expire (public maximum 90 days).
- **Long-term promotion gate** is separate, under CPE #348 and Bitmagnet #9: review rights/source boundaries, choose exact subject-specific public Git RDTE pack namespace or an approved Git-LFS/Drive object store, and persist SHA-256-addressed **small metainfo binaries** + structured Git manifests, not full payloads or the entire torrent web. Maintain source observation vs accepted CPE promotion distinction. No direct `contents:write`, release, push or permanent publication is authorized from the prototype PR.
- Avoid source amplification: Git history/source and small indexes in Git+DLE, binary metainfo under versioned controlled storage **only after review**. Cross-project consumers use stable immutable hashes and a manifest rather than fragile Actions-run URLs. Metadata retention and payload retention are independent decisions.
- Don't silently convert Bitmagnet `private=true` BEP-9/crawler captures into public corpus; that remains explicitly deferred in Bitmagnet #9.

## Gates before scaling

Independent live valid .torrent captures with native hash proof and actual indexed query; auth and provenance for all three audiences; first failure + recoverability; stable source plugin contracts and dedup across runs; capped count/storage and source rate-limits; policy adjudication per class; source-specific license/terms review; mutable upstream versions recorded by exact digest; no peer/payload until separate authorization; recurring schedule is only active once workflow lands on default branch, which is currently held. This rep does **not** establish a released/publicly distributable CPE corpus, a permanent service or a persistent object archive.
