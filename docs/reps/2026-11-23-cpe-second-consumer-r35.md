# R35 — Independent Python read-only consumer of pinned Go research projection

**2026-11-23 · DRAFT / research_only / public ORIGINAL synthetic only**

This is the smallest second-language consumer demonstration for CPE #202, built *beside* the existing Go producer in the Bitmagnet Explorer research stack. Its authority is strictly a **read-only projection consumer**, not a new reconciler, knowledge authority, source-rights issuer, package resolver, artifact hydrator or policy enforcement system.

Source parent: public BCE #50 R34 exact `4cdbe5fd19e5780225625951ad8a847ade87b623`. The source projection is generated by the existing Go `cmd/cpepack` / `cpepack.Build` path over original `testdata/cpepack` synthetic packages. Python parses it **independently** using the standard library; it does not call the Go library or issue its own knowledge snapshot.

## Minimal contract

```sh
go run ./cmd/cpepack -packages testdata/cpepack/packages.json \
  -lock testdata/cpepack/lock.json -root test.public.literature > /tmp/cpe-research-view.json

python3 -B cmd/cpepack/consumer_r35.py \
  --snapshot /tmp/cpe-research-view.json \
  --expected-lock-sha256 <independently-admitted-64-lowercase-hex> \
  --expected-snapshot-sha256 <independently-admitted-exact-byte-sha256> \
  --concept-id public:work --language th
```

The Python reader requires BOTH an expected **source-lock digest** and a **snapshot exact-byte digest**, independently supplied by the caller/owner. It compares the source-lock field and the SHA-256 of full input bytes before interpreting concepts. A matching self-asserted `lock_sha256` alone is **insufficient** to authenticate snapshot contents. The public CI synthetic probe derives its byte pin from the just-created file as a **mechanical fixture**, NOT as an issuer-authenticated owner decision; real acceptance still needs an independent signed issuer/admitted lock and rights.

Read-only output uses `authority=research_only`, `source_lock_sha256`, `concept_id`, `status`, `definition`, `lexicalizations` and `relations`. `OBSERVED` means a source-defined lexicalization exists; `NO_LEXICALIZATION` means this projection has no mapping for that language and is **not** equivalent to explicit `NO_EQUIVALENT`; `UNKNOWN_CONCEPT` means no matching identity was provided. All language tags and Unicode terms preserve exact source bytes after a strict UTF-8 parse. No translation or policy conclusion is inferred.

The parser refuses duplicate keys, malformed UTF-8, unpaired escaped surrogate strings, oversized input, unsupported schema/authority, wrong source lock or byte pin, duplicate IDs, dangling relations, repeated lexical or relationship edges and unknown fields. No external network, database, hidden trusted source, mutating operation or third-party dependency.

## Audience contracts and limits

- **Human:** a simple offline command returning the exact requested research concept; no implied policy verdict.
- **Automation:** structured JSON on stdout; stable error tokens to stderr and nonzero exit for bad snapshot/missing identity. Pin source and bytes outside the data being validated.
- **Agent:** bounded read-only query, preserving UNKNOWN/NO_LEXICALIZATION and provenance lock identity; do not call this an authenticated CPE semantic admission oracle.

This provides two independent code paths for **reading the same synthetic research snapshot**: Go producer/library and Python consumer/parser, but it is **not** proof of two independently deployed applications consuming an accepted CPE KnowledgeRelease. No actual `ConceptDiscoveryProposal` or S4/S5 rights materialization occurs. A prospective blind independent oracle remains required.
